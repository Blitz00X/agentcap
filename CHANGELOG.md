# Changelog

## 0.4.1
From the technical gate tests on real ChatGPT Plus and Claude Pro accounts (13 Nov 2026): the loop breaker stopped 4 of 4 repeat runs at the 4th identical call and the error breaker 2 of 2 failing runs (exit 4, Codex and Claude); 6 normal coding jobs (fix a test, add a feature, explain and fix) were not stopped.
- **Waiting is not looping.** A shell call that starts with `sleep N` (`sleep 4; ls done.flag`, `sleep 30 && curl ...`) no longer counts toward the loop breaker or the error streak, in the CLI (Claude hooks, Claude transcript, Codex rollout including its code-mode `exec`) and the plugin. Live, a job waiting for a file was stopped as a loop at its 4th check.
- **Claude receipts settle.** `/usage` shows a job's usage 30-90 s after its requests, so short Claude jobs read 0.0% at exit (eight gate jobs did while the account rose 7%). After a Claude job a detached `python -P -m agentcap.quota settle` keeps reading `/usage` for up to 2.5 minutes and rewrites the receipt with the settled share (`settled`, `share_pct_at_exit`). README notes that a Claude quota stop can come that much later.
- Test fixture: the fake GitHub token in the key-redaction test is built at runtime (gitleaks flagged the 0.4.0 sdist; it was never a real token).
- README and landing: macOS is marked as not yet tested on a real Mac.

## 0.4.0
Tested live on a real ChatGPT Plus account (Codex 0.166/0.167) and a real Claude Pro account (Claude Code 2.1.322/2.1.323), 11-13 Nov 2026; every defect those runs found is fixed below and covered by a test.
- **Live account quota from the agents' own clients.** `agentcap quota` asks `codex app-server` (`account/rateLimits/read`) and `claude -p /usage` for the current 5-hour and weekly %, falling back to the local readings with their age (`--local` skips the live read; `AGENTCAP_LIVE_QUOTA=0` turns it off everywhere). Neither runs a model or spends quota; AgentCap never touches a login token. A stale reading is no longer shown as the current value; an ended window says "unknown now".
- **Codex quota measured against the server.** The % in Codex's rollout is the value that came *with* a response, before it was charged, so it lags one response (live: rollout 3% after a job, server 4%). A quota job now takes its baseline from `codex app-server`, checks it every 30 s and once after exit, so the last response is in the receipt (`baseline_live`, `final_live`). An older reading from the same window is a conservative fallback.
- **Claude quota measured with `/usage`.** The statusline % lagged `/usage` by 1-2 points and its first value can be stale (live: a job that used 0% was stopped as "1%"; another ran 4% while the statusline showed 1%). A Claude job takes its baseline from `/usage`, checks it every minute, the hook also denies when `/usage` shows the limit, and the receipt is the `/usage` difference (`measured_by: usage`). The statusline is compared only with itself and never counts below the `/usage` floor.
- **Headless `claude -p` quota stop.** It has no statusline, so it used to warn and not stop. It is now stopped via `/usage` every 30 s (coarser: a 2% cap ended at 4% in a live run).
- **Codex response timeout and fail-closed.** `--response-timeout` (default `5m`, `off` disables; tool time not counted) stops one model response that runs too long (exit 4, `response_timeout`); Pro stops a job whose Codex log carries no `rate_limits` (exit 5). SIGTERM/SIGHUP still write the receipt and `done.json`; xhigh/max effort is noted at start.
- **Plugin.** `/agentcap:quota` takes its baseline from `/usage` (never another session's reading), the hook starts a background `/usage` check at most once a minute, and the self-guard now also denies `agentcap approve` from the model (live: only the CLI's env check stopped it, which `env -u CLAUDECODE` would pass).
- **Security: guard commands run with `python -P`.** The job's statusline and hooks ran `python -m agentcap.quota`, which puts the project directory first on `sys.path`: an `agentcap/` folder in the project replaced the guard (seen live with a stale copy). Upgrade from 0.3.x.
- Fix: `agentcap approve` picked a job whose process had died (approved the wrong job); only live jobs count now, and it no longer claims to clear a breaker that never tripped.
- Fix: the error breaker counted AgentCap's own denials as failing tool calls (4 + 4 denied reads tripped it after a quota pause, and approve could not clear it).
- Fix: AgentCap's messages and red alerts were written into an interactive agent's screen and overwritten its input box; they are held until the agent exits and the statusline shows `LIMIT HIT` / `PAUSED`.
- Fix: closing the terminal window lost the receipt (every write failed with EIO); started from a script under `timeout`, AgentCap froze on SIGTTOU after the agent exited. Both now finish and write the receipt.
- Fix: the terminal is restored after an interactive agent is stopped mid-turn (Codex TUI left the shell in raw mode).
- Fix: a Codex response still in flight is not reported as "no quota data"; two approvals within one poll are both reported; no 80% warning in the same reading as the stop.
- opencode Go: `--quota` estimate from opencode's cost field is documented as not reliable (Go cost reported as 0).
- README and the landing page document the limits seen live: one large response can overshoot a cap by a few points, and usage on the same account from other devices counts toward the job.

## 0.3.1
- **R5/R6: one exit-code policy for `agentcap run`** (README "Exit codes"): 2 setup/auth refusal, 3 cap, 4 loop/error/burn breaker, 5 internal error, 127 only when the command itself cannot be started. **Behaviour change for scripts:** a state/lock/HOME/ledger error (a symlinked or unreadable `quota.lock`, an unwritable `HOME`, a busy `--port`) used to print "could not start the command" and exit 127; it now prints `internal state error: could not <action> <path> (<reason>)` and exits 5. In `--cap` mode an internal `RuntimeError`/`ValueError`/`OSError` during the run used to exit 1, 2 or 127 with a summary that could say `exit code: 1`; it now stops the agent, exits 5 with reason `internal_error`, and the summary shows `exit code: 5`. The "no model requests observed" hints are no longer printed after such a stop. A missing or non-executable command still exits 127 with the same message.
- **R8: F8 edge cases.** 429/5xx answers neither count toward nor reset the rejected-credentials streak, so 401 and 429 alternating still stops with `upstream_auth_failed` on the third 401. A 403 that is not about the key/permission/account (region block, moderation/policy refusal, no readable body) is a new reason, `upstream_refused` (exit 2 after 3 in a row), advised "provider refused the request" instead of "check the API key"; it has its own streak. An agent that exits 0 right after a background rejection keeps reason `child_exit` (exit 0) and gets a separate `WARNING: the upstream rejected a request during this run` line. **Reports:** the new reason `upstream_refused` can appear in summaries, receipts and alerts.
- **R7: concurrent retry forgiveness.** A request answered 429/5xx (or rejected) now forgives only its own loop-breaker check, identified per request; before, the single-slot `forgive_last()` could undo a parallel request's check instead (a repeat hit or a failing-tool-result count could be lost). Two parallel requests, one rate-limited and retried, now keep independent counters. `forgive_last()` remains for sequential callers.
- **Opt-in in-run zombie collector (default off).** `AGENTCAP_COLLECT_ZOMBIES=1` reaps adopted zombies during `--cap`, `--quota` and harness runs, only when their session id is neither AgentCap's nor their own pid (in-group background jobs, double-forked daemons), with a `(pid, start)` re-check before `waitpid`. The agent, `setsid` helpers and AgentCap's own children are never reaped early. Without the flag nothing changes.

## 0.3.0
- **Fail-closed guards for unattended runs.** A second quota job on the same account is refused (exit 2; `AGENTCAP_ALLOW_PARALLEL=1` opts out); in quota/harness runs, unknown opencode/agy log schemas, an unreadable Codex rollout log and AgentCap internal errors stop the agent with exit 5 on Pro instead of running unguarded (in `--cap` mode an internal error also stops the agent, but not with exit 5).
- **Whole-process-tree stops.** Quota/harness stops send SIGINT to the process group, then SIGTERM, then SIGKILL (5 s / 3 s / 2 s); proxy (`--cap`) stops send SIGTERM then SIGKILL (5 s). Helpers left in the group are reaped after a normal exit. A process that changes its uid or enters another PID namespace is still out of scope.
- **Parent-death lifeline.** On Linux the guarded process starts through a small shim that arms `PR_SET_PDEATHSIG`, and a watchdog process SIGKILLs the agent's whole process group if AgentCap dies. So a SIGKILLed or OOM-killed AgentCap takes the agent with it, including a real agent started by a launcher (Codex's npm wrapper spawns the native binary as a child on Node without `process.execve`) and the agent's tool processes. A command that cannot start is still reported as "could not start the command" (exit 127), and the agent gets the same signal dispositions as a direct start (SIGPIPE/SIGXFSZ not ignored).
- **Escaped-descendant sweep (T3).** On Linux AgentCap sets `PR_SET_CHILD_SUBREAPER` for the run, adopts descendants that call `setsid()`/double-fork, and sweeps them (SIGTERM → SIGKILL, PID start-time checked) after a normal exit or stop. The same `(pid, start)` identity is held through TERM, wait and KILL, so a reused PID is never signalled. Adopted helpers that already exited are reaped, so they no longer stretch the stop/cleanup waits. Unrelated children present before the run, and anything they start, are excluded. Daemons the agent starts (a dev server, a `tmux` server, a Gradle daemon) are part of its tree and are stopped at the end of the run. A descendant AgentCap may not signal (a root-owned `sudo -b` child, a setuid program) is tried once, not waited on (before: up to ~16 s of extra exit delay), and reported as `agentcap: could not stop N process(es) (permission denied): pid ...`; it is left running and not counted as killed. Residual: a process that left the agent's group (`setsid`/daemonized) before AgentCap itself is SIGKILLed can still escape; use a container/cgroup against hostile agents.
- **Self-approval guard.** `agentcap approve` refuses inside an agent session (`AGENTCAP_QUOTA_JOB`, `AGENTCAP_GUARDED`, `CLAUDECODE`); the hook of `agentcap run --quota -- claude` denies a Bash call that runs `agentcap approve`, including quoted, escaped and `$IFS`-obfuscated forms. The Claude Code plugin's `PreToolUse` hook denies (Free and Pro) any model tool call that would run its own `scripts/agentcap_cc.py` (`approve`, `quota`, `off`, `setup`, `unsetup`, `statusline`, `hook`; any path, `python -m`, `import`, globs, quoted/escaped/`$IFS`, `bash -c`/`sh -c`) or change its state dir or installed plugin files (Bash or any tool with a `command`; Write/Edit/MultiEdit/NotebookEdit); plain reads still pass. `/agentcap:approve`, `/agentcap:quota` and `/agentcap:off` keep working because Claude Code runs a slash command's `!` line without `PreToolUse` hooks (measured on 2.1.318). Not covered: a command that never names the script or state dir (a script written elsewhere that builds the path at run time). Honest limit: a determined agent with the same OS user can still edit state; use a separate user/container against hostile agents.
- **Harness log contracts.** opencode, agy, Claude Code statusline/PreToolUse and Codex rollout fields are pinned in `agentcap/logschema.py` and checked against recorded fixtures, with an opt-in live check (`AGENTCAP_LIVE_CONTRACT=1`).
- **Private local state.** `~/.local/state/agentcap`, quota job files, the ledger, receipts and history are created 0700/0600 instead of inheriting a permissive umask. Only directories AgentCap creates, and its own default directories (`~/.local/state/agentcap`, `~/.local/share/agentcap`, `~/.config/agentcap` and their subdirectories), are made 0700; an existing directory chosen through `AGENTCAP_DB`, `AGENTCAP_RECEIPT_DIR`, `AGENTCAP_QUOTA_DIR`, `AGENTCAP_OPS_DIR` or a path argument (your `$HOME`, a project or a shared dir) keeps its mode, and no chmod follows a symlink.
- **Clearer approve message.** Approving after a loop/error stop says which breaker was cleared; at 100% it says the quota no longer stops the job instead of showing "150% of the quota".
- **opencode harness runs use `--standalone`.** Token/quota mode no longer fails when another opencode instance owns the shared managed-service port.
- Fix: proxy loop breaker missed tool loops when tool-call ids look like `call-<uuid>` (OpenRouter/opencode); hyphenated and UUID ids are now treated as volatile.
- Fix: harness token/quota cap alerts no longer print `$?` placeholders; quota alerts show the limit and a rounded share.
- Fix: harness quota share never goes backwards between polls (final summary showed 0.00%).
- Fix: no spurious "reported an API error" line after agentcap's own stop.
- Fix: quota deny is a pause the model resumes after `agentcap approve`, not a permanent stop.
- Fix: same-window % jitter (12→13→12) no longer counts as a window reset (inflated share to 13%).
- Fix: failing tool calls are counted live via Claude Code `PostToolUse`/`PostToolUseFailure` hooks, so parallel batches reach the error breaker.
- Fix: 429/5xx retries (identical resends) count neither as a repeated step nor as failing tool calls; the attempt that finally gets through counts once, so a loop whose every step needs one retry still stops at the 4th step.
- Fix (F8): an upstream that rejects the credentials or account (HTTP 401/402/403, Gemini 400 `API_KEY_INVALID`) is reported plainly (`upstream rejected the request (HTTP 401: User not found.) — check the API key for <host>; nothing was spent.`, provider message truncated and key-redacted) instead of as a runaway loop; the agent's resends no longer count toward the loop breaker. Three rejections in a row stop the run with reason `upstream_auth_failed`, exit 2; if the agent gives up first its exit code is kept.
- `--quota` help now lists agy and says opencode exposes no quota.
- **opencode and agy (Antigravity CLI) support.** `agentcap run --tokens N -- opencode run ...` / `-- agy -p ...` reads the agent's own JSON event stream (`opencode run --format json`, `agy --output-format stream-json`) and enforces a token cap, the loop breaker (same tool call 4x) and the error breaker (8 failing tool calls in a row); stop is SIGINT. `--log-cap USD` caps on opencode's own cost estimate (for subscriptions such as opencode Go).
- **agy quota mode:** `agentcap run --quota 5% --window 5h -- agy -p ...` reads `remaining_fraction` from `agy -p /quota --output-format json` (no agent turn, no quota spent) for the model's group. opencode exposes no quota %, so `--quota` is refused for it with a pointer to `--tokens`/`--log-cap`.
- **$ mode:** `agentcap run --cap 1 -- opencode run -m agentcap/<model> ...` injects a provider through `OPENCODE_CONFIG_CONTENT` (user config untouched, run forced `--standalone`); `agy` is routed through the Gemini API route (`modelProvider: gemini`, `GEMINI_API_KEY`).
- Pricing: the launch-week end date is no longer hard-coded in the package; the pricing page shows the current date.
- Version 0.3.0 (package and plugin manifest).
- Packaging: the internal task/notification tracker `agentcap.ops` is no longer shipped in the wheel or sdist (it stays in the repository).

## 0.2.2
- Codex quota under 1% (`--quota 0.5%`) now prints a warning at start. Codex reports quota in whole percent, so such a cap cannot trigger until a full 1% is used (seen in a real ChatGPT-plan run). README note added.
- Fix: `agentcap approve` on a Codex or headless job that was already stopped with SIGINT said "the run continues" and used up an approval. It now says the job was already stopped and changes nothing. Found in a real Codex run on a ChatGPT plan on 30 Oct.

## 0.2.1
- **Interactive Claude Code stays open on a stop.** The quota and loop stops deny the tool call and end the turn (`continue: false`), in the plugin and in `agentcap run --quota -- claude`. An interactive session is no longer sent SIGINT while the hook works. Headless `claude -p` runs and Codex are still stopped with SIGINT. If the hook never fires, SIGINT is still the fallback.
- **`agentcap approve` / `/agentcap:approve` (Pro).** Raises a stopped job's or session's limit by 50%, at most twice, and clears a loop-breaker streak so the run can continue. Free never blocks, so there is nothing to approve.
- **Receipts name the last tool call.** Only the tool name is stored, never its input.
- **`agentcap waste`:**
  - Cache misses are split into main session and subagents.
  - Subagent misses get a `subagentPromptCacheTtl: "1h"` tip.
  - New `STARTING CONTEXT` line: first-request tokens per subagent.
- **Fix: cache-miss $ in `waste`.** A 5-minute re-write was priced at the 1-hour write rate (2x input). It now uses 1.25x input for 5-minute writes and 2x for 1-hour writes, so 5-minute misses were overstated before. History import now prices 1-hour cache writes at 2x input; before, they were priced at 1.25x.
- README: a Codex $20 plan example, a comparison with spend-stop and RelayPlane, and the main vs subagent cache facts as Anthropic stated them.
- Version 0.2.1 (package and plugin manifest).

## 0.2.0
- **Safer license activation**: `agentcap license activate` with no key prompts with hidden input on a terminal; `agentcap license activate -` (or piped stdin) reads the key from stdin; `AGENTCAP_LICENSE_KEY` is honoured. A key passed as an argument still works but lands in shell history, so docs now recommend the prompt.
- **Pricing copy**: Pro is $12 one-time during launch week (until 10 Nov), then $19.
- **`agentcap waste`** (Free, read-only): subagent/Opus share, cache misses, repeated tool calls and error streaks from local Claude Code and Codex logs, with a "Pro would have stopped this at $X" line.
- **`agentcap report --by agent`**: subagent lineage tree (Claude sidechains, Codex sub-threads).
- **Quota-mode loop breaker** (`agentcap run --quota N% -- claude|codex`): same tool call (name + input) 4 times in a row or 8 failing tool calls in a row stops the job on Pro (exit 4, `loop_detected`); Free prints what Pro would have done. Polling tools (`wait`, `sleep`, `write_stdin`, `TaskOutput`, `BashOutput`, ...) never count.
- **Claude Code plugin loop breaker**: `PreToolUse` denies the 4th identical call with `continue: false` (Pro) or shows one notice (Free); new `PostToolUse`/`PostToolUseFailure` hooks stop after 8 failing calls. State is hashes and counters only, pruned after 7 days on `SessionStart`.
- **Behaviour change: proxy loop threshold 5 → 4.** `agentcap run --cap` (API proxy) now blocks the 4th identical request instead of the 5th, matching every other breaker and the docs.
- Fix: `agentcap --help` crashed (unescaped `%` in the `budget` help text).
- Plugin manifest version 0.2.0; VS Code/Cursor extension `agentcap-0.2.0.vsix`.
- README and landing repositioned around "see where your agent wastes money, stop the loop".
