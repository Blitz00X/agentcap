How it works

  1. Wrap the command

    agentcap run --cap 2 -- codex exec "fix the failing tests"
agentcap run --cap 2 -- gemini -p "refactor utils.py"
agentcap run --cap 2 -- python my_agent.py

    Uses your API key (OPENAI_API_KEY / GEMINI_API_KEY). ChatGPT or Google sign-in (OAuth/subscription) traffic is not metered.

  2. Requests go through the proxy

    AgentCap routes supported CLIs automatically: it injects a Codex provider override for Codex CLI and a temporary GEMINI_CLI_HOME overlay for Gemini CLI (your ~/.gemini is linked, settings.json is copied with api-key auth; nothing in ~/.gemini is modified). For your own script it sets OPENAI_BASE_URL and GOOGLE_GEMINI_BASE_URL for the child. It meters POST /v1/responses and /v1/chat/completions — Codex CLI uses the Responses API — and Gemini generateContent / streamGenerateContent. Before each request it reserves the worst-case cost and lowers the output limit to what is left.

  3. The cap stops the run

    At the cap it blocks the request and kills the child process group (SIGTERM, then SIGKILL after 5 s), then prints the reason in the terminal. The run exits with code 3 — or 4 when Pro's repeated-request breaker fires, which can also send webhook and Telegram alerts.

This is a local spend cap, not a mathematical guarantee. With conservative reservation it reserves worst-case cost before each request, so overshoot is rare but possible when providers count more tokens than estimated.

Install

pipx install agentcap-cli

(installs the agentcap command)

No pipx? macOS: brew install pipx && pipx ensurepath; Linux: python3 -m pip install --user pipx && python3 -m pipx ensurepath.

Then put a cap on a run:

# Codex CLI (API-key mode) — routed through AgentCap automatically
agentcap run --cap 2 -- codex exec "fix the failing tests"

# Gemini CLI (API-key mode) — routed via a temporary GEMINI_CLI_HOME overlay
agentcap run --cap 2 -- gemini -p "refactor utils.py"

# Gemini CLI in a folder you have not trusted yet
agentcap run --cap 2 --trust-workspace -- gemini -p "refactor utils.py"

# your own script, if it honours OPENAI_BASE_URL / GOOGLE_GEMINI_BASE_URL
agentcap run --cap 2 -- python my_agent.py

Both CLIs must be in API-key mode — see Supported & tested for versions and auth.

Works with Claude Max / ChatGPT subscriptions (quota mode)

No API key? Cap one job's share of your subscription limit instead: agentcap run --quota 5% -- claude stops the job after it used 5% of your weekly quota (--window 5h for the 5-hour window). Works with Claude Code and Codex.

  • Read-only. AgentCap never touches your subscription login, tokens or traffic. It reads Claude Code's official statusline rate_limits and Codex's local session logs, then stops the local agent (Claude Code PreToolUse hook, then SIGINT).
  • Your settings are not edited: Claude Code gets a one-run --settings layer, and your own statusline keeps working.
  • 80% warning, per-job receipt ("this job used 4.2% of the weekly quota"), Telegram/webhook alerts on Pro.

Honest limits: the percentage is account-level (parallel sessions count, we warn), a job can overshoot by up to one request, and Claude reports limits only in interactive sessions. FAQ

Does it see my prompts or keys?

Prompts and keys pass through the local proxy in memory; AgentCap never stores or uploads them. Free sends nothing anywhere. Pro sends alert metadata (run id, spend, reason) only to webhook/Telegram destinations you configure, and validates your licence key with Polar about once a week.

Is it a mathematical guarantee?

No. AgentCap applies a local spend cap with conservative reservation: it reserves worst-case cost before each request, so overshoot is rare but possible when providers count more tokens than estimated, for example due to server-side system prompts, tool schemas, images or tokenizer differences. You get an overshoot alert if a settlement exceeds its reservation.

Which CLIs and versions are supported?

Codex CLI 0.163 (codex exec, API key via OPENAI_API_KEY) and Gemini CLI 0.58–0.66 (gemini -p, GEMINI_API_KEY) are routed automatically. See Supported & tested.

What is the loop/burn breaker?

Pro stops a run (exit code 4) before the next request is sent when the agent repeats the same step 4 times in a row (last tool call and its result, ignoring the growing history), gets 8 failing tool results in a row, or spends more than --max-burn (default $2/min) over a rolling 2-minute window.

Tested on simulated growing-history transcripts (Claude Code and OpenAI tool loops); 50 simulated normal sessions did not trip it. It cannot catch every no-progress loop, which is why the run cap still applies.

Does it work with subscription/OAuth logins?

No. API-key traffic is metered, so Codex CLI and Gemini CLI must run in API-key mode. ChatGPT or Google sign-in (OAuth/subscription) traffic is not metered.

Which providers does it support?

OpenAI-compatible and Gemini APIs. Prices come from a local table you can override.

Does clamping output hurt quality?

Yes, it can: when the budget is tight AgentCap lowers max output tokens so the call fits; answers can be shorter or cut off. Use --no-clamp to refuse instead.

Does stopping roll back what the agent did?

No. At the cap AgentCap sends SIGTERM then SIGKILL; files or remote changes already made stay. Use git / small steps.

Is the ledger my provider bill?

No. It is a local estimate from published prices and reported usage; when usage is missing it charges the full reservation (conservative). Your provider invoice is authoritative.

Is the day cap shared across machines?

No. Hour/day caps (Pro) are per machine (local SQLite ledger). A license covers 3 machines, each with its own budget.
