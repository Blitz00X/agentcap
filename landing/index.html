Local spend cap for unattended API-key runs

The API-key guard for unattended Codex CLI and Gemini CLI runs.

AgentCap runs Codex CLI or Gemini CLI behind a local proxy on 127.0.0.1, caps spend for the run, clamps the output limit when the budget runs short, and kills the local process at the cap — then prints why.

An unattended run can spend while you are away

A looping agent or a long unattended Codex CLI / Gemini CLI run can burn money on API keys while you are not watching. Provider budget alerts are delayed and usually do not stop anything — by the time the email arrives, the spend has already happened.

How it works

  1. Wrap the command

    agentcap run --cap 2 -- codex exec "fix the failing tests"
agentcap run --cap 2 -- gemini -p "refactor utils.py"
agentcap run --cap 2 -- python my_agent.py

    Uses your API key (OPENAI_API_KEY / GEMINI_API_KEY). ChatGPT or Google sign-in (OAuth/subscription) traffic is not metered.

  2. Requests go through the proxy

    AgentCap sets OPENAI_BASE_URL and GOOGLE_GEMINI_BASE_URL for the child, so requests go through the local proxy. It meters POST /v1/responses and /v1/chat/completions — Codex CLI uses the Responses API — and Gemini generateContent / streamGenerateContent. Before each request it reserves the worst-case cost and lowers the output limit to what is left.

  3. The cap stops the run

    At the cap it blocks the request and kills the child process group (SIGTERM, then SIGKILL after 5 s), then prints the reason in the terminal. The run exits with code 3 — or 4 for a detected loop in Pro, which can also send webhook and Telegram alerts.

Install

pipx install agentcap-cli

(installs the agentcap command)

Then put a cap on a run:

# Codex CLI (API-key mode)
agentcap run --cap 2 -- codex exec "fix the failing tests"

# Gemini CLI (API-key mode)
agentcap run --cap 2 -- gemini -p "refactor utils.py"

# your own script, if it honours OPENAI_BASE_URL
agentcap run --cap 2 -- python my_agent.py

Both CLIs must be in API-key mode — see How it works for what is metered.

FAQ

Does it see my prompts or keys?

No. Nothing about prompts, responses or keys is stored — just token counts, costs, model names, timestamps and request hashes.

Is it a mathematical guarantee?

No. The cap is enforced before each request with a conservative reservation. If a provider bills more input tokens than estimated, final spend can exceed the cap by at most one request's estimation error, and you get an overshoot alert.

Does it work with subscription/OAuth logins?

No. API-key traffic through OPENAI_BASE_URL / GOOGLE_GEMINI_BASE_URL is metered, so Codex CLI and Gemini CLI must run in API-key mode. ChatGPT or Google sign-in (OAuth/subscription) traffic is not metered.

Which providers does it support?

OpenAI-compatible and Gemini APIs. Prices come from a local table you can override.
