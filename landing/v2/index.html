01 The problem

Agents do not stop themselves. Invoices do not arrive in time.

A loop is cheap to start and expensive to notice.

A looping agent, or a long unattended run, can spend for hours while nobody is watching. Provider budget alerts are delayed, and most of them do not stop anything. By the time the email lands, the spend has already happened.

02 The stop

Wrap the command. Three things happen.

  1. 01

    Wrap the run

    Put AgentCap in front of the agent and give it one limit: a share of the weekly quota for a subscription, or a dollar cap for an API key.

    $ agentcap run --quota 5% -- claude
$ agentcap run --cap 2 -- codex exec "fix the failing tests"
  2. 02

    AgentCap watches the run

    For subscriptions it asks the agents themselves: Claude Code’s statusline and its own /usage, Codex’s session logs and its own codex app-server. No model call, no quota spent. For API keys, requests go through a proxy on 127.0.0.1. Your login, tokens and settings are not touched.

  3. 03

    At the limit, it stops

    With an API key, the next request is blocked and the process group is stopped: SIGTERM first, SIGKILL after five seconds. On a subscription, Claude Code’s next tool call is denied and the session stays open for agentcap approve; Codex and headless runs get SIGINT. The terminal says why, the receipt is saved, and the run exits with code 3. The loop breaker exits with 4.

Honest limit: this is a local spend cap, not a mathematical guarantee. Worst-case cost is reserved before each request, so overshoot is rare but possible when a provider counts more tokens than estimated, for example in server-side system prompts, tool schemas or images.

Quota mode: the quota % comes from the agent itself and arrives once per model response, so one large response can take a job past its limit by a few points. Usage on the same account from anywhere else (claude.ai, the desktop or phone app, another terminal) counts toward the job too.

07 Questions

The honest answers.

Does it see my prompts or keys?

Prompts and keys pass through the local proxy in memory. AgentCap never stores or uploads them. Free sends nothing anywhere. Pro sends alert metadata only (run id, spend, reason) to the webhook or Telegram destination you configure, and validates your licence key with Polar about once a week.

Is it a mathematical guarantee?

No. AgentCap applies a local spend cap with conservative reservation: it reserves worst-case cost before each request, so overshoot is rare but possible when providers count more tokens than estimated — for example server-side system prompts, tool schemas, images or tokenizer differences. You get an overshoot alert if a settlement exceeds its reservation.

Which CLIs and versions are supported?

Codex CLI 0.163 (codex exec, API key via OPENAI_API_KEY) and Gemini CLI 0.58–0.66 (gemini -p, GEMINI_API_KEY) are routed automatically. See Install for the verified versions.

What is the loop and burn breaker?

Pro stops a run (exit code 4) before the next request is sent when the agent repeats the same step four times in a row (last tool call and its result, ignoring the growing history), gets eight failing tool results in a row, or spends more than --max-burn (default $2/min) over a rolling two-minute window.

Tested on simulated growing-history transcripts for Claude Code and OpenAI tool loops; 50 simulated normal sessions did not trip it. It cannot catch every no-progress loop, which is why the run cap still applies.

Does it work with subscription or OAuth logins?

The proxy does not meter OAuth traffic. Quota mode is different: it reads the % from the agents themselves (Claude Code’s statusline and /usage, Codex’s logs and codex app-server), then stops the local job. It never touches the login or the traffic. ChatGPT and Google sign-in traffic is not metered by the dollar cap.

Which providers does it support?

OpenAI-compatible and Gemini APIs, plus Anthropic for Claude Code API-key runs. Prices come from a local table you can override.

Does it need an account or a server?

No. It runs locally on your machine. There is no dashboard and no service to deploy.

Does clamping output hurt quality?

Yes, it can. When the budget is tight, AgentCap lowers the max output tokens so the call fits; answers can be shorter or cut off. Use --no-clamp to refuse the request instead.

Does stopping roll back what the agent did?

No. At the cap AgentCap sends SIGTERM, then SIGKILL; files or remote changes already made stay. Use git and small steps.

Is the ledger my provider bill?

No. It is a local estimate from published prices and reported usage. When usage is missing it charges the full reservation, which is conservative. Your provider invoice is authoritative.

Is the day cap shared across machines?

No. Hour and day caps are per machine (local SQLite ledger). A licence covers three machines, each with its own budget.
